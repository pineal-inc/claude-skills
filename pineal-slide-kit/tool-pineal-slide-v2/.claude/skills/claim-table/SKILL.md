# claim-table

書く前の主張表と、書いた後の読者テストをまとめた共通手順。
媒体固有の条件は、各媒体の手順書が持つ。

| 媒体 | 手順書 |
|---|---|
| コラム | pineal-corp-site の `docs/seo-column/pipeline-v4.md`、`docs/seo-column/figure-design.md` |
| スライド | このリポジトリの `.claude/skills/pineal-slide/SKILL.md`、`references/visual-assets.md` |

## 主張表

初稿の前に作り、依頼者の確認を取る。確認が取れるまで本文を書かない。

| 列 | 書くこと |
|---|---|
| 位置 | タイトル、説明文、見出し、図、スライドのページ |
| 主張 | 読者に持ち帰ってほしいことを述語まで書いた1文 |
| 証拠 | 実画面、ログ、公表文、数値、元資料のページ。パスか URL で辿れる形 |
| 見せ方 | 下の「素材の既定」から選ぶ |

- 証拠のない主張は、削るか「推測」と書く
- 主張を並べて読み、話がつながるか確かめる
- 主張の段階で一般語で書く。判定を避けるための言い換えをしない

## 語彙表

主張表の下に、本文で使う語だけを載せる。

- 載せる語
  - 製品名、制度の名称、業界で定着した語、読者が検索する語
- 載せない語
  - 書き手が作った言い方、略称の思いつき
- 同じものに2つの呼び名を使わない
- 迷った語は検索して、出典か読者の語彙にあることを確かめる

## 素材の既定

ロゴ、スクショ、図解は、依頼者が言わなくても多く入れる。主張表の全行に見せ方を割り当てる。

上から順に探す。媒体の手順書に素材の順序があるときは、そちらを優先する。

| 順 | 素材 | 使う場面 |
|---|---|---|
| 1 | 現物 | 公表文、実画面、実物の成果物、元資料の図の切り出し |
| 2 | ロゴ | 会社名、製品名、ツール名が出る箇所 |
| 3 | 図 | 順序、分岐、3要素以上の関係、2軸の比較 |
| 4 | 表 | 同じ項目で並べて比べられる内容 |

- 出典のある主張には、公表文や画面の現物を添える
- 会社名、製品名を挙げたら、その場にロゴを添える
- 見せ方が空の行を残さない
  - 置けないときは「文字のみ」と理由を書く
- 置かない素材
  - 箇条書きを箱で囲み直しただけの図
  - 実測値のないグラフ、やっていない工程の図
  - 主張と関係のない飾り
- 数を埋めるために置かない
  - 主張から外せる素材は外す

## 読者テスト

本文と素材ができた後、機械チェックの前に行う。

- 実行
  - sonnet の subagent を読者役ごとに分けて起動する
  - 編集の経緯、主張表、語彙表を渡さない
- 読者役
  - 媒体の手順書が指定する2種類
  - 例: 検索から来た検討者と採用候補者、提案先の決裁者と現場の担当者
- 親の仕事
  - 指摘を1件ずつ採否する。全部は直さない
  - 公式語と定着語への指摘は不採用にする
  - 素材を直すときは、媒体の規則に従う
- 書き換え
  - 指摘箇所だけを直す
  - 全文の言い換えを重ねない
- 記録
  - 指摘の件数、採用した件数、主張表と読み取りがずれたページを媒体の記録先へ残す

### subagent への指示

波括弧を埋めて渡す。

```markdown
あなたは{読者役}です。{文書の種類}を初めて読みます。

## 読むもの
{本文のパス、または各ページの画像のパス}
{図のパス}

## 答えること
1. 語: 意味が一度で取れない語、書き手が作った言い方、意味と内容がねじれた語、詰めた複合語、同じものの呼び分け
2. 導入: 読み始めて違和感のある箇所と、その理由
3. 図: 図を3秒だけ見て、何の図に見えるか。読み取った結論を1文で書く
4. 離脱: 読むのをやめたくなる箇所と、その理由
5. 残ったこと: 読み終えて、{読者役}として持ち帰ったことを3つ

## 答え方
- 強い順に最大20件。各件に箇所と、自然な言い方の案を1つ添える
- 内容の正しさは評価しない
- 褒めなくてよい
- Bash でファイルを読むときは cd を使わず絶対パスで行う
```

5の答えを主張表の主張と突き合わせる。ずれた箇所は、本文か素材の順序を直す。
