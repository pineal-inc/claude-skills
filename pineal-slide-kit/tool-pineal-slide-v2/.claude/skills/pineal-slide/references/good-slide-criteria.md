# 良いスライドの判断基準（Chain-of-Thought 用）

Phase 3 の視覚配置設計で使う判断基準。各スライドに対してこの基準に照らして考える。

---

## 原則 1: 1スライド = 1メッセージ

スライドは「説明する場所」ではなく「主張を視覚で証明する場所」。
1枚のスライドで伝えることは1つだけ。複数の主張は複数枚に分割する。

**判断チェック**: 「このスライドを一言で言うと？」が即答できるか。
できなければスライドを分割するか、メッセージを絞る。

---

## 原則 2: 見出しは h1、結論は `.lead`

> **文体の正本（必読）** → `~/.claude/rules/document-tone-rules.md`

要素の役割分担だけをここで定める。h1 はスライドの見出し、`.lead` は結論を置く要素。
**h1 と `.lead` に何を書けるか（条件・型・Fail 記号・修正の型・例）は正本が定義する。
ここには再掲しない**。生成時も検収時も正本を読んでから判定する。

---

## 原則 3: 視覚要素は情報の「型」に合わせる

情報には型がある。型に合わないレイアウトは認知コストを上げる。

| 情報の型 | 最適なコンポーネント |
|----------|-------------------|
| A vs B の比較 | `.card.before` + `.card.after`（grid-2）|
| 並列する選択肢・特徴 | `.card.feature` x N（grid-2 / grid-3）|
| 時系列・手順 | `.flow-container` + `.flow-step` |
| 数値・KPI・インパクト | 見せ方は正本「表記の共通ルール」による（`.dashboard` / `.highlight-box` は legacy 専用） |
| 割合・量的比較 | `.bar-chart` + `.bar-fill` |
| テキスト中心（引用・証言） | `.testimonial` or `.card.feature` |
| 画像 + 説明 | `.grid-2`（左：テキスト、右：画像プレースホルダー）|
| 表形式データ | `<table>` with inline style |

---

## 原則 4: 情報密度をコントロールする

1枚に詰め込みすぎると読まれない。

**適切な密度の目安（16:9 スライド / 720pt x 405pt）:**
- テキスト: 最大150文字/スライド
- 箇条書き: 最大5項目、1項目30文字以内
- カード: 最大3枚（grid-3）、各カード80文字以内
- 数値: 見せ方は正本「表記の共通ルール」による（`.dashboard` / `.highlight-box` は legacy 専用）

**情報が多すぎる場合の対処:**
- 枚数を増やす（1枚を2枚に分割）
- サブタイトル（h2）で補足し、本文を削減する
- 詳細は `<small>` タグで小さく添える

---

## 原則 5: 読み手に求める理解・判断・実行から選ぶ

「何を感じさせるか」ではなく、**読んだ人が何を理解し、何を判断し、何を実行すべきか**で
コンポーネントを選ぶ。本文の文体は正本 R5・R6 による（条件はここに再掲しない）。

| スライドの役割 | 読み手に求めるもの | コンポーネント選択の方針 |
|------|---------|----------------------|
| 現状・課題の提示 | 現状と課題の差分を理解する | before/after で差分を並置する |
| 対応方針の提示 | 提案内容を理解する | feature カードで方針を並べる |
| 実績・事例の提示 | 実現可能性を事実で確認する | 実測値を示す（見せ方は正本「表記の共通ルール」による） |
| 次の手順の提示 | 誰がいつ何をするかを判断する | flow で次の手順を明示する |
| 表紙 | 資料の主題と対象を把握する | title-slide（ダーク背景） |

---

## 原則 6: 視覚的階層を守る

h1 > h2 > h3 > 本文 の優先度を崩さない。

- **h1**: スライドの見出し。20pt、アクセントバー付き（色は配色の正本による）。R1〜R4 の判定対象
- **`.lead`**: 結論を置く要素。12pt。件数・文数・字数の契約は `pineal-validate/skill.md` の Phase 0 が正本、文体は R5〜R6（どちらもここに再掲しない）
- **h2**: 補足の見出し。12pt、グレー。R1〜R4 の判定対象
- **h3（カテゴリ）**: カード内の見出し。10pt（色は配色の正本による）
- **本文**: 証拠・詳細。9pt

h1 と `.lead` の書き方は正本が定義する（ここには再掲しない）。

---

## CoT 実行テンプレート

各スライドに対して以下を順番に実行する：

```
【スライド N の判断】
Step 1 (見出しと結論): .lead → 「___」／ h1 → 「___」
        （書き方は正本を読んでから決める。.lead の分量の契約は Phase 0）
Step 2 (情報の型): 比較 / 数値 / プロセス / リスト / テキスト / 画像+説明
Step 3 (情報量): 多い → 分割検討 / 普通 → そのまま / 少ない → シンプルに
Step 4 (読み手): 対象者はこれを読んで何を理解し、何を判断し、何を実行すべきか
Step 5 (コンポーネント): → [選択したコンポーネント名] を使う理由: ___
```
