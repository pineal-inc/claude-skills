# pineal-slide-v3

pinealのテンプレートに沿った**提案書パワポ**を、Claude Code で作成・改修するためのスキル。

## セットアップ

キット直下の `setup.sh` がまとめて行う（手順はキットの README）。
このフォルダを `~/.claude/skills/` へリンクする必要はない。`pineal-slide` スキルの `pptx/pptxlib.py` がキット内の場所を自動で見つける。

---

## これは何か

「いい感じにスライドを作って」を実現するスキル**ではない**。
pinealの提案書を**決まった手順・決まった寸法で**組み立てるための、かなり手続き的な道具立て。

同梱しているもの:

| | |
|---|---|
| `assets/pineal_temp.pptx` | テンプレ本体（**唯一の正**）。フォント・レイアウト12種・型スライド16枚 |
| `references/` | デザインシステム／型カタログ／**地雷集14件**／設計書の雛形 |
| `scripts/` | スライド生成・結合・テキスト置換・フォント変更・目視QA |

---

## 癖があります（先に読んでください）

このスキルには**意図的な縛り**が3つある。窮屈に見えるが、いずれも事故って入れたもの。

### 1. pptxを1枚も作る前に、設計書(md)を書く

いきなりスライドを作らない。まず `設計書/提案書_パワポ設計書.md` に全ページの
**メッセージライン（そのページで言い切る一文）**を書き、それだけを縦に並べて音読する。

```
S02 pinealは、マーケ領域を含む◯◯様の複数部門でご支援実績があります
S03 本プロジェクトは、現状整理と仕組みづくりの2段階で進めます
S04 ...
```

ここで筋が通らなければ構成が破綻している。**図を作ってから構成を直すのは高コスト**なので、
この段階で潰す。雛形は `references/design-doc-template.md`。

### 2. スライド1枚 = 1フォルダ

```
パワポ/
├ 改修ログ.md                  ← 変更を1行ずつ追記
├ S01_表紙/
│   ├ S01_表紙.pptx
│   └ old/S01_表紙_20260731_1441.pptx
├ S02_エグゼクティブサマリ/
│   ├ S02_エグゼクティブサマリ.pptx
│   ├ old/
│   └ photos/ logos/ images/   ← そのページの素材だけを置く
└ 統合版/
    ├ <案件>_統合版.pptx        ← 作業用。常に再生成物
    └ 20260727_ご提案書（pineal）_〇〇.pptx   ← 提出版。凍結して触らない
```

1枚のpptxを全員で編集すると、**どこをいつ誰が変えたか追えなくなる**。分けておくと:

- 改修が1枚に閉じる（他ページを壊さない）
- `old/` でページ単位の履歴が追える
- 素材をそのページの近くに置ける
- **統合版を「いつでも捨てて作り直せるもの」として扱える**

### 3. 作ったら必ずレンダリングして目視する

python-pptx は**テキストの折返しを計算しない**。
「文字を入れた」だけでは、箱からはみ出て見切れているか、隣と重なっているか、
下端 7.5in を超えて切れているかが**一切わからない**。

```bash
python3 scripts/visual_qa.py --file <deck>   # → JPEGが出るので目で見る（PowerPointで描画）
```

このステップを飛ばすと必ず崩れが残る。実際に何度も残した。

## 使い方

### 1枚作る

```bash
# 型カタログ（references/template-catalog.md）で近い型を探してから
python3 scripts/new_slide.py \
    --out "パワポ/S03_プロジェクト理解/S03_プロジェクト理解.pptx" \
    --source-slide 10 --keep-body \
    --title "与件整理｜プロジェクト理解" --message "……"
```

As-Is/To-Be・マイルストン・タイムライン・体制図・見積表は**既に型がある**。
ゼロから組むより速くて綺麗。

### 統合版にまとめる

```bash
python3 scripts/merge_deck.py build --slides-dir パワポ --out "パワポ/統合版/〇〇_統合版.pptx"
```

**既存デッキがある場合は `build` を使わない。**

| やりたいこと | コマンド |
|---|---|
| 既存ページのテキスト修正 | `patch_text.py --deck <統合版> --replace "旧" "新"` |
| 末尾に1枚追加 | `merge_deck.py append --deck <統合版> --slide <個別pptx>` |

`build` は全ページを組み直すため、プレースホルダーの継承が切れて
**タイトル/メッセージラインのフォントが飛ぶ**（→ `references/pitfalls.md` の 1）。

### スクリプト一覧

| | |
|---|---|
| `new_slide.py` | テンプレから1枚取り出してスライドフォルダ＋pptxを起こす |
| `merge_deck.py build / append` | 統合版の生成／末尾に1枚追加 |
| `patch_text.py` | 統合版のテキストを直接置換（件数検証つき・`--dry-run`可） |
| `set_font.py inspect / font / title-size` | フォントとタイトルサイズの調査・一括変更 |
| `apply_standard.py` | 既存デッキに標準（タイトル位置・リード文の✓）を後から適用 |
| `visual_qa.py` | PDF経由で画像化して目視QA |

いずれも `old/` に自動退避する。

## 固定ポイント（全ページ・全デッキで揃える）

| 用途 | pt |
|---|---:|
| タイトル | **28** |
| リード文（行頭に ✓） | **18** |
| セクション見出し | **14** |
| 脚注 | **8** |

タイトルとリード文は**レイアウトから継承**されるので、新規スライドでは何もしなくてよい。
箱のタイトル・本文は情報量に応じて可変。詳細は `references/design-system.md`。

## clone したら1回だけ

pptxの `git diff` を読めるようにする設定を有効化する。

```bash
bash tools/setup_git_textconv.sh
```

この紐付けは `.git/config` に入る＝**コミットされない**ため、clone のたびに必要。
設定すると、バイナリなのに中身が読める。

```
## SLIDE 8 (slide8.xml)
-  ダミータイトル
+  差分テスト用タイトル
```

ただし**表示されるのはテキスト・スライド順・ノートまで**。
フォント名や座標の変更は差分に出ない（保存はされるので、その版には戻せる）。
フォント一括置換などをしたときは、**コミットメッセージに書き残すこと**。

---

## 注意

- **フォントは Meiryo UI**（Microsoft Office 同梱）。`visual_qa.py` は既定で
  **実際の PowerPoint に描画させる**ので、書体もレイアウトも実機と一致する。
  実行中は PowerPoint が前面に出るので触らないこと。対象を開いたままだと失敗する。
  PowerPoint が無い環境は `--engine libreoffice`（ただし**書体は置換される**）。
- 公開版のテンプレは、社内情報（役員の写真・経歴、クライアントロゴ、連絡先）を載せた4・5・6・15枚目の中身を外してある。
- 提出済みファイルは**別名で凍結**し、以降の改修は作業用の統合版だけに入れる。
