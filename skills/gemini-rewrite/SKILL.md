# gemini-rewrite

Claude が内容を固めたものを、Gemini に人間らしい日本語へ書き直させる。判断や事実の追加は Gemini に任せない。

## 平文モード(メール・Slack返信)

1. Claude 側で内容(伝える順序、判断、要望)を確定した下書きを作る
2. 実行
   ```
   printf '%s' "$DRAFT" | python3 ~/.claude/skills/gemini-rewrite/scripts/gemini_rewrite.py --brief "宛先は〇〇さん、8行以内、口調はやわらかめ"
   ```
3. 出力を目視で確認し、直した語があれば1行で報告する
   - 文体ルールを持っていれば、それに照らす。ピネアルの文体ルールは、このリポジトリの `pineal-slide-kit/rules/` にある
4. ユーザーにはコードブロックで本文だけ出す

## 記事モード(Markdown 記事のループ書き換え)

公開済みまたは執筆済みの Markdown 記事を、意味を変えずに「人が書いた自然な文」へ寄せる。

```
python3 ~/.claude/skills/gemini-rewrite/scripts/article_loop.py content/column/foo.md /tmp/out --rounds 3
```

- 仕組み: 最初に sonnet が記事全体から用語集を抽出する。次に frontmatter を外し、コードフェンス外の h2 で節に分割。節ごとに Gemini 書き換え → 機械チェック + sonnet の意味照合 → 指摘を Gemini に戻して再書き換え。指摘ゼロか rounds 到達で確定
- sonnet の呼び方は `--checker` で選ぶ。既定は `agent`(`claude -p` を使わない)
  - `agent`: スクリプトは照合用プロンプトを `<outdir>/checks/` に書き出し、終了コード 3 で止まる。表示された指示文を1件ずつ Agent ツール(`model: sonnet`、general-purpose)に並列で渡し、全件の JSON がそろったら表示された同じコマンドを再実行する。終了コード 0 と「完了」が出るまで繰り返す(用語集で1回、巡回ごとに1回止まる)
  - 指示文は書き換えずにそのまま渡す。subagent に照合の基準を足したり、呼び出し元が代わりに判定したりしない
  - subagent は同じ照合指示でも「迷ったら書かない」に強く従い、A〜C の1語差を落としやすいため、agent モードだけ「1文ずつ対応させ、迷ったら fact_changed を付けて入れる」補足を足している(5節で比較: 事実が変わる指摘は `claude -p` 8件、補足なし subagent 9件、補足つき 13件)
  - `cli`: `claude -p --model sonnet` で照合し、止まらずに最後まで進む。Claude Code の外から回すとき用。`GEMINI_REWRITE_CHECKER=cli` でも切り替えられる
  - 途中で照合方式を変えると別の途中結果として扱うため、outdir を分ける
- 機械チェック: 見出し・コード・表・画像行・HTMLコメントの完全一致、数値とリンクURLの多重集合一致、用語集の語の出現回数が減っていないか、禁止語、文字数 ±25%
- 用語集: 節単位の照合では記事全体の用語のずれが見えないため、用語集を Gemini への指示と機械チェックの両方に使う。抽出結果は `<outdir>/glossary.txt`。`--glossary <file>`(1行1語)で差し替え、`--glossary none` で無効
  - 入れるのは製品名、制度の名称、定着した専門用語だけ。書き手の造語を入れると言い換えから守られ、違和感のある語が最後まで残る。実行前に `glossary.txt` を読み、造語を消す
- 意味照合は「実害のある問題だけ」を指摘する緩い設定。語彙や語尾の差は指摘しない(厳しくすると原文に引き戻されて変化が小さくなる)
  - ただし断定の強まり、主体・関係の変化、限定の語の消失の3つは、語尾や助詞1語の差でも指摘する(緩い設定のままだと、公開済みの記事3本で事実の強さが変わる書き換えが素通りした)
  - 照合役が `fact_changed: false` を付けた指摘(表現の差だけ)は差し戻さない
  - 差し戻しでは「前回の書き換えを土台に、指摘箇所だけ直す」と指示する。「原文に戻す」とだけ書くと節全体が原文へ引き戻される(実測: 原文との一致率 0.84 → 0.96)
- `cli` で `claude -p` が失敗したとき(未ログイン、タイムアウト、JSON で返らない)は1回再試行し、駄目なら中断する。エラー文を指摘として Gemini に戻さない
- `agent` で subagent の JSON が読めないときは、スクリプトが該当ファイル名を出して止まる。そのファイルを消して、その1件だけ subagent をやり直す
- `--tone casual` で口調を「ほんの少しだけカジュアル」にする(X Article・個人ブログ向け)。原文の文をベースに語尾と接続だけ崩す最小書き換え
  - 既定の `standard` は原文から離れて書き直すため、常体混じり・口語の原文は丁寧・硬い方向へ戻る(「作ってません」→「作っていません」)。くだけた原文に既定を当てない
  - frontmatter のない Markdown もそのまま渡せる
- `--sections 2,3` で節番号を絞れる(0 は導入)。`--model` / `GEMINI_REWRITE_MODEL` でモデル変更
- 出力: `<outdir>/final.md` が完成形。`s{NN}-r{N}-issues.json` で残った指摘を確認する
- 適用は Claude が行う。`final.md` と原文の diff を見て、残指摘のある節は原文に戻すか手で直す。導入や連載案内など守りたい段落は適用時に元へ戻す
- `--tone casual` の出力を当てるときの選別
  - 採用: 語尾の軽い崩し(「〜しています」→「〜してます」、「〜です」→「〜なんです」)、硬い語の言い換え(「一組にした」→「セットにした」)、軽い「正直」「そのまま」
  - 「んですよね」は記事全体で2か所まで。Gemini は段落ごとに足すので、超えた分は原文に戻す
  - 箇条書きの体言止め・常体に「です・ます」が付いたら戻す(丁寧化になる)
  - 冒頭1文目のくだけ(「〜流れてきたんですよね」)、日本語として座りの悪い語順(「ちょっと1段落だけ」)、原文にない動作の宣言(「書いてみます」)は戻す
- 一文一行の記事は、適用後に `。` で改行を戻す(コード・表・箇条書き・インデント行は触らない)
- 記事に独自のチェック(リンク切れ、表記ルールなど)があれば、適用後に通す

## 採否の目安

Gemini の書き換えは全部は当てない。Claude が diff を見て、次のものは原文に戻す。

- 意味が変わる言い換え
  - 例: 「かける時間」→「所要時間」
- 資料や記事のほかの箇所と用語がずれる言い換え
  - 例: 「Teams の入口」→「Teams の窓口」
- 硬い語への言い換え
  - 例: 「軽い、重いの目安」→「軽重の目安」

## 前提

- Python 3(標準ライブラリだけで動く)
- Gemini API キー
  - 環境変数 `GEMINI_API_KEY` から読む
  - 無ければ macOS の Keychain から読む。サービス名の既定は `GEMINI_API_KEY` で、`GEMINI_KEYCHAIN_SERVICE` で変えられる
  - Keychain への登録例: `security add-generic-password -a "$USER" -s GEMINI_API_KEY -w`(実行するとキーの入力を求められる)
- 既定モデルは `gemini-4-argon`
  - Gemini 4 は Hydrogen(速い・安い)、Argon(汎用)、Carbon(最上位・遅い)の3種。書き直しには Argon を使う
  - 大量に回すときは `--model gemini-4-hydrogen` を試す
- 記事モードは Claude Code のセッションから回す前提(照合を subagent に任せるため)。`--checker cli` のときだけ `claude` コマンドのログインが要る
- `gemini` CLI は使わず、REST API を直接呼ぶ
